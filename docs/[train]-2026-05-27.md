# Báo cáo tiến độ thử nghiệm NACIR

> **Ngày báo cáo:** 2026-05-27  
> **Phạm vi:** Training / loss experiment  
> **Dataset chính:** VN3K Vietnamese  
> **Baseline chính:** LoRA + Curriculum Circle Loss, seed 2400, T2I R@1 = 52.28  
> **Log run mới nhất:** `artifacts/training/logs/output.log`  
> **Trạng thái tổng quát:** NACIR đã pass notebook controlled validation, nhưng full clean training với FN branch bật bị giảm accuracy. Hướng tiếp theo là chứng minh detector-off no-op và thử FP-only trên noisy correspondence.

---

## 1. Tóm tắt quyết định

NACIR không nên thay thế trực tiếp Circle Loss trên VN3K sạch ở cấu hình full hiện tại.

Run clean NACIR đầu tiên dùng candidate từ notebook:

```text
loss.NACIR=true
loss.nacir_config.fn_prior=0.010
loss.nacir_config.epsilon_n=0.60
```

Kết quả tốt nhất:

```text
Best checkpoint: epoch=48-val_score=50.70.ckpt
Test T2I R@1: 50.70
Delta vs Circle baseline seed 2400: -1.58 R@1
```

Nguyên nhân hợp lý nhất: trên clean VN3K, FP detector không kích hoạt vì GMM luôn fallback, còn FN branch suppress một phần hard negatives thật nên làm yếu cơ chế hard-negative mining của Circle Loss.

---

## 2. Trạng thái từng nhánh NACIR

| Thành phần | Trạng thái | Kết luận |
|---|---:|---|
| Loss-level no-op | Pass | `compute_noise_aware_circle()` bằng Circle khi detector tắt |
| Synthetic FN notebook | Pass sát ngưỡng | FN posterior xếp known-FN cao hơn true negatives, nhưng no-collapse chỉ vừa qua ngưỡng |
| Synthetic FP notebook | Pass mạnh | GMM tách corrupted vs clean rất rõ |
| Mini fine-tune notebook | Pass | R@1 ổn định, `+0.02` |
| Full clean NACIR | Fail clean-safe | T2I R@1 giảm xuống `50.70` |
| FP branch trên clean run | Inactive | GMM fallback toàn bộ |
| FN branch trên clean run | Có khả năng gây hại | Suppress hard negatives khi dataset không có đủ FN thật |

## 6. Kết luận kỹ thuật

Không nên claim:

```text
Full NACIR improves clean VN3K.
Full NACIR automatically no-ops on clean VN3K.
```

Có thể claim:

```text
NACIR loss-level no-op is correct when detectors are disabled.
Synthetic FP branch reacts strongly to controlled noisy correspondence.
Synthetic FN branch reacts in the right direction but is fragile.
Full clean NACIR currently hurts clean VN3K, likely due to FN suppression.
```

VN3K không nhất thiết sạch tuyệt đối, nhưng với cơ chế hiện tại:

```text
Không có đủ noisy-positive signal để GMM FP detector kích hoạt.
Không có đủ true-FN signal để FN suppression tạo lợi ích trên clean training.
```

## 7. Chạy gì tiếp theo

### 7.1 Clean detector-off NACIR

Mục tiêu: chứng minh training-level no-op khi detector tắt.

```bash
bash run_nacir.sh \
  loss.nacir_config.fn_enable_epoch=999 \
  loss.nacir_config.fp_enable_epoch=999
```

Kỳ vọng:

```text
T2I R@1 gần Circle baseline.
Nếu vẫn giảm mạnh, lỗi nằm ở wiring/training path của NACIR.
Nếu gần baseline, lỗi nằm ở detector policy.
```

### 7.2 Clean FP-only NACIR

Mục tiêu: kiểm tra FP branch có an toàn trên clean VN3K không.

```bash
bash run_nacir.sh \
  loss.nacir_config.fn_enable_epoch=999
```

Kỳ vọng:

```text
GMM fallback hoặc clean_weight_mean gần 1.0.
R@1 gần Circle baseline.
```

### 7.3 Noisy correspondence A/B tại `noisy_rate=0.4`

Chạy vanilla Circle:

```bash
uv run trainer.py -cn cir_msiglip \
  dataset.noisy_rate=0.4 \
  dataset.noisy_file=artifacts/training/noiseindex/VN3K_VI_0.4.npy \
  trainer.max_epochs=60 \
  trainer.accumulate_grad_batches=3 \
  ++trainer.precision=16-mixed \
  optimizer=cir_test \
  optimizer.param_groups.default.lr=1e-4 \
  +lora=default
```

Chạy FP-only NACIR trên cùng noise file:

```bash
bash run_nacir.sh \
  dataset.noisy_rate=0.4 \
  dataset.noisy_file=artifacts/training/noiseindex/VN3K_VI_0.4.npy \
  loss.nacir_config.fn_enable_epoch=999
```

Mục tiêu: trả lời câu hỏi FP branch có giúp khi caption bị shuffle hay không.

## 8. Metric cần theo dõi

| Metric | Kỳ vọng nếu run tốt |
|---|---|
| `val_t2i_R1` / `test_t2i_R1` | Không tụt trên clean; tụt ít hơn Circle trên noisy |
| `gmm_separation` | Clean có thể < 1; noisy nên > 1 nếu FP detector bắt được noise |
| `gmm_fallback` | Clean có thể `True`; noisy nên chuyển `False` ở rate đủ cao |
| `nacir_clean_weight_mean` | Clean gần 1.0; noisy thấp hơn 1.0 |
| `nacir_alpha_p_scale_mean` | Clean gần 1.0; noisy giảm |
| `nacir_alpha_n_scale_mean` | Với FP-only phải gần 1.0 vì FN tắt |

## 10. Quyết định hiện tại

Giữ **LoRA + Curriculum Circle Loss** làm kết quả chính cho clean VN3K.

Không bỏ NACIR, nhưng đổi mục tiêu:

- Full NACIR không dùng làm default clean replacement.
- FN branch giữ cho controlled/synthetic FN research.
- FP-only NACIR là hướng ưu tiên cho noisy correspondence.
- Detector-off NACIR là run cần thiết để chứng minh clean no-op ở training level.
