\section{Evaluation Parameters}

To rigorously assess the performance of the proposed Multilingual Text-Based Person Search framework, I adhere to the standard evaluation protocols used in cross-modal retrieval and person re-identification. The retrieval process is conducted as follows: given a textual query $T_q$, the system computes the cosine similarity scores between $T_q$ and all gallery images $\{I_g\}$. The gallery images are then ranked in descending order of similarity.

\noindent The quality of this ranking is quantified using three primary metrics: Cumulative Matching Characteristics (CMC), Mean Average Precision (mAP), and Mean Inverse Negative Penalty (mINP).

\subsection{Rank-k Accuracy}

\noindent \textbf{Rank-k Accuracy}, derived from the Cumulative Matching Characteristics (CMC) curve, is the most intuitive metric for retrieval tasks. It measures the probability that at least one correct matching image of the target identity appears within the top-k retrieved results.

\begin{itemize}
    \item \textbf{Definition:} For a set of $Q$ text queries, let $r(q)$ be the rank position of the first correct match for the $q\text{-th}$ query. The Rank-k accuracy is calculated as:
    \[
    \text{Rank-k} = \frac{1}{Q} \sum_{q=1}^{Q} \mathbb{I}(r(q) \leq k)
    \]
    where $\mathbb{I}(\cdot)$ is the indicator function, returning 1 if the condition is true and 0 otherwise.

    \item \textbf{Significance:}
    \begin{itemize}
        \item \textbf{Rank-1:} This is the most critical indicator of system performance. It reflects the system's ``First-Hit'' capability---i.e., whether the system can identify the suspect immediately at the very top of the list.
        \item \textbf{Rank-5 and Rank-10:} These metrics evaluate the robustness of the system. They account for scenarios where visual ambiguity (e.g., severe occlusion or lighting changes) might push the correct match slightly down the list, but it remains within a scrollable range for human operators.
    \end{itemize}
\end{itemize}

\subsection{Mean Average Precision (mAP)}

\noindent While Rank-k focuses only on the position of the \textit{first} correct match, Mean Average Precision (mAP) evaluates the overall quality of the entire ranked list. This is particularly important for the person search task where a single identity may have multiple corresponding images in the gallery (multi-shot retrieval).

\begin{itemize}
    \item \textbf{Definition:} mAP is the mean of the Average Precision (AP) scores over all queries. First, the Average Precision for a single query $q$ is computed as:
    \[
    AP(q) = \frac{1}{N_{gt}} \sum_{k=1}^{N} P(k) \times rel(k)
    \]
    where:
    \begin{itemize}
        \item $N_{gt}$ is the total number of ground-truth images for the query.
        \item $N$ is the size of the gallery.
        \item $P(k)$ is the precision at rank $k$.
        \item $rel(k)$ is an indicator function equal to 1 if the image at rank $k$ is a match, and 0 otherwise.
    \end{itemize}

    \item Finally, mAP is averaged over all queries:
    \[
    mAP = \frac{1}{Q} \sum_{q=1}^{Q} AP(q)
    \]

    \item \textbf{Significance:} A high mAP indicates that the model is consistent. It ensures that \textit{all} relevant images of the target person (front view, back view, side view) are retrieved and clustered at the top of the ranking list, rather than just finding the easiest match.
\end{itemize}

\subsection{Mean Inverse Negative Penalty (mINP)}

\noindent \textbf{Mean Inverse Negative Penalty (mINP)} is a strict metric designed to evaluate the worst-case performance of the retrieval system, specifically targeting the ``hardest positive'' samples.

\begin{itemize}
    \item \textbf{Definition:} For a query $q$, the Inverse Negative Penalty (INP) measures how deep the \textit{hardest} correct match is buried in the ranking list. It is defined as:
    \[
    INP(q) = 1 - \frac{R_{hardest} - N_{gt}}{N - N_{gt}} \approx 1 - \frac{R_{hardest}}{N}
    \]
    where $R_{hardest}$ is the rank position of the \textit{last} correct match in the list. The mINP is the average of INP over all queries.

    \item \textbf{Significance:}
    \begin{itemize}
        \item If $R_{hardest}$ is very large (the last correct image is at the bottom of the list), INP approaches 0.
        \item If all correct images are at the very top, INP approaches 1.
        \item \textbf{Relevance to Circle Loss:} Since the objective of this project is to improve ``Hard Negative Mining'' and ``Hard Positive Maintenance'' using Circle Loss, mINP is a crucial metric. An improvement in mINP proves that the Circle Loss successfully pulls even the most difficult-to-recognize views of an identity closer to the query embedding.
    \end{itemize}
\end{itemize}

\subsection{Ablation Study and Impact Analysis}

\noindent To isolate the contribution of each component---LoRA, Circle Loss, and the Curriculum Schedule---I conducted systematic ablation studies. A particularly important control isolates the batch-size effect from the loss contribution.

\subsubsection{Full Fine-Tuning Control at Matched Batch Size}
\label{sec:ft_control}

\noindent Because LoRA enables a 3$\times$ larger batch size than full fine-tuning on the same hardware, one could plausibly argue that the observed gains arise from optimization dynamics (richer negative pools) rather than from the proposed loss function. To rule out this confound, I conducted a \textit{matched-batch} full fine-tuning control. Specifically, I trained all 376M parameters at the identical batch configuration as LoRA (batch size 24, gradient accumulation 3, effective batch 72) on an RTX 4090 (24GB), using the same schedule (60 epochs, cosine LR, AdamW) but without Circle Loss. Results are shown in Table~\ref{tab:ft_control}.

\begin{table}[htbp]
\centering

\label{tab:ft_control}

\noindent Three key observations follow from this controlled comparison:
\begin{itemize}
    \item \textbf{Batch size is not the source of improvement.} At an identical effective batch size of 72, full fine-tuning (49.18\%) \textit{underperforms} LoRA (49.90\%) by 0.72\%. With 376M trainable parameters, full fine-tuning overfits on the small Vn3K training set (2,000 identities, 4,302 images). The low-rank constraint of LoRA acts as an implicit regularizer that prevents this overfitting.
    \item \textbf{Circle Loss contribution is cleanly isolated.} The improvement from adding Curriculum Circle Loss on top of LoRA---measured at the same batch size---is +2.38\% R@1 (49.90\% $\to$ 52.28\%). This gain cannot be attributed to any batch-size artifact.
    \item \textbf{The two components are complementary.} LoRA regularization prevents overfitting on the low-resource dataset, while Circle Loss adds discriminative structure through hard-negative mining. Neither component alone exceeds the combined framework.
\end{itemize}

\noindent Applying Circle Loss with a fixed weight improves Rank-1 from 49.90\% to 50.53\%, confirming that the adaptive re-weighting mechanism of Circle Loss provides superior discriminative signals compared to the uniform penalty of the Sigmoid function. \begin{itemize}
    \item \textit{Reasoning:} The Sigmoid-based N-ITC loss excels at establishing a coarse global alignment but lacks fine-grained precision. Conversely, Circle Loss enforces strict local discrimination but generates high-variance gradients that can destabilize training if applied too early---a phenomenon analyzed in detail in Chapter~4. The curriculum strategy mitigates this by allowing a warm-up phase for global alignment, followed by a ramp-up phase for hard mining, effectively synergizing the strengths of both objectives.
\end{itemize}

\section{Summary of Empirical Findings}

\noindent Across all four experimental settings, the proposed mSigLIP-CLoRA framework delivers consistent and statistically stable improvements over the TBPS-mSigLIP baseline:

\begin{itemize}
    \item \textbf{3000VnPersonSearch (Vietnamese, low-resource):} +2.58\% Rank-1 (49.70\% $\to$ 52.28\%), confirmed across three seeds with std.\ $<$0.75\%.
    \item \textbf{CUHK-PEDES (English, high-resource):} +1.09\% Rank-1 (70.76\% $\to$ 71.85\%), showing no degradation in the high-resource regime.
    \item \textbf{PRW-TPS-CN (Chinese, low-resource, logographic):} +12.57\% Rank-1 (46.78\% $\to$ 59.35\%), the largest gain observed.
    \item \textbf{10\% CUHK-PEDES (English, data-scarce):} +10.37\% Rank-1 (46.73\% $\to$ 57.10\%), validating robustness under severe data scarcity.
    \item \textbf{Full fine-tuning control (Section~\ref{sec:ft_control}):} at matched effective batch size (72), full FT (49.18\%) underperforms LoRA (49.90\%), conclusively ruling out batch size as the source of improvement.
\end{itemize}

\noindent Taken together, these results support the central thesis claim: mSigLIP-CLoRA is most effective in \textit{multilingual low-resource adaptation}, while remaining competitive and non-harmful in high-resource settings. The theoretical basis for this asymmetric benefit is developed in Chapter~4, and the practical deployment of the trained model on edge hardware is presented in Chapter~6.
