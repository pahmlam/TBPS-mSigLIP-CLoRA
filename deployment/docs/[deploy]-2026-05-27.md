# Báo cáo tiến độ deploy mSigLIP lên Qualcomm RB3 Gen2

> **Ngày báo cáo:** 2026-05-27  
> **Thiết bị mục tiêu:** Qualcomm RB3 Gen2 / QCS6490 / HTP V68  
> **Model nguồn:** mSigLIP LoRA + Curriculum Circle Loss, checkpoint `epoch=56-val_score=52.28.ckpt`  
> **Baseline accuracy:** VN3K text-to-image R@1 = 52.28%  
> **Trạng thái tổng quát:** Vision encoder đã chạy được trên HTP; binary INT8 real-calibration bằng API mới cũng chạy được nhưng fidelity fail (`cosine_l2_mean = 0.1300`).

---

## 1. Tóm tắt 

Đã deploy được **vision encoder** lên RB3 và chạy thật bằng QNN HTP runtime. Runtime đã pass: graph load được, chạy đủ input, output đúng shape, không NaN/Inf, profiling hợp lệ. Latency hiện tại khoảng **22.25 ms/image** theo NetRun và **20.72 ms/image** ở accelerator.

Vấn đề còn lại là **độ đúng của embedding sau quantization**. Binary hiện tại được compile bằng dummy calibration (`--calibration_data none`), nên QNN embedding lệch rất xa PyTorch/ONNX baseline:

```text
QNN vs PyTorch/ONNX cosine_l2_mean = 0.1727
```

Dataset calibration thật 500 ảnh VN3K đã upload thành công. Đường CLI cũ `j5wx6x63p` fail vì AI Hub vẫn inject `--preserve_io_datatype`, nhưng đường Python API mới đã tạo được `vision_encoder_calib500.bin` và chạy được trên board. Tuy nhiên binary này vẫn **không đạt fidelity**:

```text
QNN vs PyTorch cosine_l2_mean = 0.1300
cosine_l2_min/max = 0.0799 / 0.1774
```

Do đó pipeline hiện tại chứng minh runtime HTP hoạt động, nhưng **chưa có binary vision đủ đúng để dùng cho retrieval/accuracy**.

### GIẢI THÍCH:
**LoRA merge + FP16/FP32 export**

Đây là bước lấy checkpoint training `.ckpt`, merge LoRA vào backbone chính, rồi xuất ra model inference thuần:

```text
model_fp32.pt
model_fp16.pt
config.yaml
```

Mục tiêu là bỏ optimizer/training state và tạo model dễ export/deploy hơn. FP32 dùng làm baseline chính xác, FP16 dùng để giảm size/RAM.

**ONNX export vision encoder**

Vision encoder được tách riêng thành ONNX:

```text
image 1x3x256x256 -> embedding 1x768
```

ONNX là format trung gian để Qualcomm AI Hub compile sang QNN context binary. File nằm ở:

```text
artifacts/deployment/exports/exported_model/vision_onnx/
```

**ONNX export text encoder**

Text encoder cũng đã export sang ONNX:

```text
input_ids + attention_mask -> embedding 1x768
```

Nhưng hiện chưa compile/chạy trên HTP, vì đang ưu tiên giải quyết fidelity của vision encoder trước.

**Compile vision INT8 dummy-cal**

Đây là lần compile vision encoder sang QNN context binary với INT8 nhưng dùng:

```text
--calibration_data none
```

Nó tạo được `vision_encoder.bin`, job `jgkr7qwn5`, chứng minh pipeline compile HTP hoạt động. Nhưng vì không có calibration thật, accuracy không đáng tin.

**Chạy vision trên RB3 HTP**

Đã copy `vision_encoder.bin` lên board và chạy bằng:

```text
qnn-net-run --backend libQnnHtp.so --retrieve_context vision_encoder.bin
```

Kết quả là graph load được, execute được, sinh output cho 10 ảnh VN3K. Nghĩa là model đã chạy thật trên HTP/DSP, không phải CPU.

**Profiling vision trên RB3**

Đã đo latency bằng `qnn-profile-viewer`.

Kết quả chính:

```text
NetRun avg:      ~22.25 ms/image
Accelerator avg: ~20.72 ms/image
HVX threads:     4
```

Tức là tốc độ runtime ổn cho vision encoder.

**Output validity**

Kiểm tra file output từ QNN:

```text
10/10 output
mỗi output = 768 float32
không NaN/Inf
output không giống hệt nhau
```

Nghĩa là runtime không lỗi và output có cấu trúc đúng.

**Fidelity QNN vs PyTorch**

Đây là bước quan trọng nhất hiện tại.

Ta so sánh embedding từ QNN với embedding từ PyTorch/ONNX trên đúng cùng raw input. Kết quả với dummy-cal:

```text
cosine mean = 0.1727
```

Kết quả với binary real-calibration `vision_encoder_calib500.bin`:

```text
cosine mean = 0.1300
```

Cả hai mức này đều quá thấp. Binary dummy-cal và binary calib500 đều chạy được nhưng embedding sai nhiều, chưa dùng cho retrieval được.

**Real calibration dataset**

Đã tạo/upload calibration dataset thật từ 500 ảnh VN3K train:

```text
Dataset ID: d7x5gzne9
```

Dataset này dùng để AI Hub tính quantization range tốt hơn thay vì dùng dummy calibration.

**Compile vision INT8 real-cal**

Đã thử 2 đường:

```text
Job ID: j5wx6x63p
Flow: deprecated submit-compile-job --quantize_full_type int8
Status: failed, vì vẫn preserve float I/O
```

```text
Job ID: jpr9v62vp
Flow: submit_quantize_job + submit_compile_and_link_jobs
Status: compile/link success, tạo vision_encoder_calib500.bin
Board runtime: pass
Fidelity: fail, cosine_l2_mean = 0.1300
```

`j5wx6x63p` dùng calibration thật `d7x5gzne9`, nhưng đã fail. Log cho thấy `qairt-converter` và `qairt-quantizer` vẫn nhận `--preserve_io_datatype image output_0`, nên I/O không được quantize sang INT8. HTP reject ở bước context binary với lỗi:

```text
Tensor 'image' has a floating-point type which is not supported by the targeted device.
Please quantize the model including its I/O and try again.
```

`jpr9v62vp` giải quyết được lỗi compile/link nhưng chưa giải quyết được độ đúng embedding. Vì vậy calibration dataset dùng được và HTP runtime dùng được, nhưng cấu hình quantization hiện tại vẫn chưa phù hợp cho embedding retrieval.

**Compile text encoder HTP**

Chưa làm. Lý do là nếu vision encoder còn sai do quantization, compile text encoder bây giờ chưa có ý nghĩa. Cần vision pass fidelity trước.

**End-to-end retrieval trên board**

Chưa làm. Retrieval cần cả vision encoder và text encoder đều chạy đúng, sau đó mới tính cosine similarity để search. Hiện mới vision runtime pass, chưa accuracy pass.

## 4. Vấn đề hiện tại

Binary `vision_encoder.bin` dummy-cal chạy được nhưng fidelity fail:

```text
num_samples = 10
cosine_l2_mean = 0.1727
cosine_l2_min = 0.1440
cosine_l2_max = 0.2424
l2_l2_mean = 1.2861
```

Binary `vision_encoder_calib500.bin` real-cal cũng chạy được nhưng fidelity còn thấp hơn:

```text
num_samples = 10
cosine_l2_mean = 0.1300
cosine_l2_min = 0.0799
cosine_l2_max = 0.1774
l2_l2_mean = 1.3189
any_qnn_nan = false
any_qnn_inf = false
```

Mức cosine này quá thấp cho embedding retrieval. Vì PyTorch và ONNX Runtime khớp nhau trên cùng raw input, nguyên nhân hiện tại không còn có thể quy đơn giản cho dummy calibration. Cần cô lập fidelity loss xảy ra ở QDQ ONNX sau quantize hay ở QNN compile/runtime/I/O.

Quyết định kỹ thuật:

- Không mở rộng sang `vn3k_test_100` hoặc full retrieval với binary dummy-cal/calib500.
- Không compile text encoder trước khi vision encoder pass fidelity.
- Tập trung debug quantization fidelity của vision encoder trước.

```text
Preprocess: RGB -> resize 256x256 bicubic -> ToTensor -> Normalize(0.5, 0.5)
```

Đã submit compile job với real calibration:

```text
Job ID: j5wx6x63p
```

Command đã dùng:

```bash
qai-hub submit-compile-job \
  --model artifacts/deployment/exports/exported_model/vision_onnx/ \

  --compile_options " --target_runtime qnn_context_binary --quantize_full_type int8" \
```

## 6. Việc cần làm tiếp theo

### Bước 1: Dừng dùng command `submit-compile-job --quantize_full_type int8` cho vision

Job `j5wx6x63p` đã xác nhận command này vẫn preserve float I/O. Nếu chạy lại cùng kiểu command, khả năng cao sẽ fail cùng lỗi.

### Bước 2: Chuyển sang QAI Hub Python API mới

Mục tiêu là tách quantize và compile/link:

```text
submit_quantize_job(model, calibration_data=d7x5gzne9, int8/int8)
submit_compile_and_link_jobs(quantized_model, device="Dragonwing RB3 Gen 2 Vision Kit")
```

Helper script đã có thể chạy từ local:

```bash
venv/bin/python deployment/scripts/qnn/submit_qaihub_quantize_compile.py \
  --model artifacts/deployment/exports/exported_model/vision_onnx/ \
  --calibration-data d7x5gzne9 \
  --wait \
  --download artifacts/deployment/qnn_inputs/vision_encoder_calib500.bin
```

Ghi chú: với `qai_hub 0.48.0`, không truyền thẳng string `d7x5gzne9` vào `submit_quantize_job`, vì API sẽ hiểu nó là đường dẫn file local. Helper script đã resolve dataset ID bằng `hub.get_dataset("d7x5gzne9")` trước khi submit.

Ghi chú tiếp theo từ job `jp13422k5`: `submit_quantize_job` vẫn fail nếu ONNX input còn dynamic batch. Helper script hiện tự tạo bản:

```text
artifacts/deployment/exports/exported_model/vision_onnx_static/
```

và rewrite input:

```text
image: ['batch_size', 3, 256, 256] -> [1, 3, 256, 256]
```

Kết quả mới từ log `jpr9v62vp`: compile với ONNX static/QDQ đã **pass**. Converter không còn `--preserve_io_datatype`, QNN DLC asset `mq389x29m` được upload, và local đã có:

```text
artifacts/deployment/qnn_inputs/vision_encoder_calib500.bin
size: ~90 MB
```

Log vẫn có warning `Following OPs fallback to float` và nhiều warning signed-offset, nên đây chưa phải là accuracy pass.

Yêu cầu kiểm tra trong log mới:

```text
Không được có --preserve_io_datatype image output_0
Context binary phải được tạo thành công
```

### Bước 5: Cô lập lỗi fidelity

Thứ tự debug tiếp theo:

1. Tải hoặc xuất được **QDQ ONNX sau quantize** từ quantize job.
2. So sánh QDQ ONNX vs PyTorch trên `vn3k_test_10`.
3. Nếu QDQ ONNX đã thấp: lỗi nằm ở PTQ/calibration/quantization config, cần thử cấu hình quantize khác.
4. Nếu QDQ ONNX tốt nhưng QNN thấp: lỗi nằm ở compile/runtime/I/O QNN, cần kiểm tra native I/O encoding, output tensor, hoặc thử QNN CPU/HTP đối chiếu.

Helper để chạy bước 2 sau khi có QDQ ONNX:

```bash
venv/bin/python deployment/scripts/qnn/compare_onnx_with_pytorch.py \
  --onnx-model artifacts/deployment/qnn_inputs/<downloaded_qdq_onnx_or_dir> \
  --model-dir artifacts/deployment/exports/exported_model \
  --input-dir artifacts/deployment/qnn_inputs/vn3k_test_10 \
  --precision fp32 \
  --json artifacts/deployment/qnn_outputs/vn3k_test_10_calib500/qdq_vs_pytorch_summary.json \
  --csv artifacts/deployment/qnn_outputs/vn3k_test_10_calib500/qdq_vs_pytorch.csv
```

## 7. Rủi ro còn lại

| Rủi ro | Mức độ | Cách xử lý |
|---|---:|---|
| Real calibration vẫn làm embedding lệch mạnh | Cao | Dùng `submit_quantize_job` + `submit_compile_and_link_jobs`; kiểm tra QDQ ONNX; xem xét mixed precision / exclude layer nhạy |
| Text encoder lớn hơn vision do embedding table | Trung bình | Chỉ compile text sau khi vision pass; kiểm tra memory/profile riêng |
| INT8 làm giảm cross-modal alignment | Cao | Đo QNN-vs-PyTorch cosine trước, sau đó mới đo VN3K R@1 |
| AI Hub API/CLI deprecated flags thay đổi | Trung bình | Ưu tiên Python API mới khi compile lại |
| Output QNN là dequantized float32 nhưng graph I/O native là U8 | Trung bình | Luôn dùng cùng script compare để tránh hiểu nhầm format |

---

## 8. Kết luận

Deployment đã qua được cột mốc khó nhất về runtime: **vision encoder chạy thật trên RB3 HTP**. Tuy nhiên, binary hiện tại chưa đạt yêu cầu accuracy vì được quantize bằng dummy calibration.

Mốc quyết định tiếp theo không còn là chờ job `j5wx6x63p`; job này đã fail vì preserve float I/O. Mốc tiếp theo là tạo được binary INT8 real-calibration bằng flow mới không preserve I/O float.

Nếu binary real-calibration mới cho fidelity tốt, pipeline sẽ chuyển sang:

1. benchmark `vn3k_test_100`;
2. đo full VN3K retrieval/R@1;
3. compile text encoder;
4. ghép end-to-end demo trên board.

Nếu compile flow mới vẫn fail hoặc fidelity vẫn thấp, cần dừng mở rộng benchmark và sửa pipeline quantization trước.
